Partners

Build on SHINRAI.

Your product, on your customers’ own hardware.

Some organisations cannot send their data to a cloud service, so cloud-only AI products cannot reach them. SHINRAI gives your product a way in: as an ISHIZUE plugin, or as an MCP server running on the customer’s machines, beside the models they approved.

Talk to us about partnering

Who this is for

For products that need to run where the data is.

  • AI startups with products

    Reach customers who need your product on their own hardware.

  • International companies bringing AI to Japan

    ISHIZUE’s interface is in Japanese and English, and it runs on hardware your customers in Japan control.

  • System integrators

    Build each client’s edition from our standard layers, the client’s own layer and the products they need.

  • Makers of models, workstations and on-premises compute

    Give the models and machines you offer a harness that routes work to them and records what they did.

  • Enterprises shaping their own edition

    Add your own plugins, skills and settings in a layer that updates leave in place.

What your product stands on

Your product brings its tools. ISHIZUE brings the rest.

  • A router and its decision engine

    Auto reads each request on the computer, picks one of the models the organisation approved and writes the choice to the session log.

  • Agents

    Up to ten tool calls at once, helper agents in the background, plans to approve and goals that last across turns.

  • Files

    Real files in a workspace, with each turn’s changed files listed and open to review.

  • Memory

    Memory, Knowledge Brain and Graph RAG, kept as files on the computer and searched by keyword with no network call.

  • A record

    Each model request, tool call and result in the Trajectory, and a session log on the computer.

  • An edition for each customer

    A layer of configuration over one core we maintain, and your product can be part of it.

  • A network ledger

    A list a security reviewer can check: each feature we know can reach the network, its default and what goes out.

How a product joins

Three ways in.

  1. 1

    An ISHIZUE plugin

    It adds tools, commands, background jobs, settings or a model connection.

  2. 2

    An MCP server

    Written in any language. It runs as a local program or as a service on the network.

  3. 3

    Skills

    Procedures, written down, that load when a task needs them.

The MCP client is not part of the default set-up; the organisation’s edition adds it.

What ISHIZUE expects of a product

  • It makes no model calls of its own: ISHIZUE’s agent calls its tools. An MCP server cannot use ISHIZUE’s model, because ISHIZUE does not support MCP sampling.
  • Network use stays off until allowed, and third-party hosts are blocked by default.
  • Results come back as text, images and file paths.
  • Calls time out after 60 seconds unless configured otherwise, so longer work should return at once and finish in the background.
  • Plugin code runs outside the command sandbox, and approvals do not cover plugin tools yet.
  • Installs come from a folder, a package file, a package registry or a code-hosting server; the last two reach the network, as the network ledger shows. There is no marketplace.
