ISHIZUE · 礎 · foundation stone

The foundation
your AI stands on.

ISHIZUE is an AI harness: the layer that connects models, tools, memory and permissions, and runs agents on top of them. Its name comes from 礎 (ishizue), the stone a building rests on. Everything in it is a plugin, including the agent loop, so each organisation gets an edition shaped to its work.

Router

Every request, to a model that suits it.

In the Mac app, conversations run through Auto, the local router, unless you choose another model. It reads the request, rules out what can’t do the job, ranks what can and records why. It can only choose among models on your own machines.

Developer preview

  1. 01

    Admit only private models

    Model apps running on this Mac (Ollama, LM Studio, vLLM, SGLang and llama.cpp), plus one approved workstation on your private network over HTTPS. Public internet addresses are refused.

  2. 02

    Rule out what can’t do the job

    Models whose context window can’t hold the request, that can’t read an attached image, or that aren’t cleared for tool use are set aside before any scoring.

  3. 03

    Read the task

    A fixed reader for Japanese and English sorts the message into one of eight kinds (quick, chat, agentic, reasoning, code, maths, vision, long) and judges how hard it is. No model is called and no prompt tokens are spent.

  4. 04

    Rank once

    One decision scores every remaining model and thinking mode together: the smallest suitable model for a quick reply, the strongest with thinking on for hard work.

  5. 05

    Answer, or move once

    If the chosen model fails before it starts answering, Auto moves once to the next ready model. It never moves to a hosted model.

  6. 06

    Record why

    The choice and its reasons are written to the chat’s record, and the chat shows which model answered.

Decision engine

Decisions you can audit.

Behind Auto is a decision engine with a simple promise: the same inputs give the same answer. It weighs each candidate on five factors, and holds back when two options are too close to call.

In testing

The five factors and their weights

  1. ×4 Fit for the task (×4) Does this model and thinking mode suit this kind of task?
  2. ×2 Size fit (×2) The smallest model for a quick reply, the strongest for hard work.
  3. ×2 What you taught it (×2) Your model switches, ratings and retries. Older lessons fade, counting half after 14 days. Stored on your Mac.
  4. ×1 Placement (×1) On this Mac, or on your workstation.
  5. ×−2 Recent failure (×−2) A model that failed this kind of task in the last 15 minutes steps aside.
  • The weights are deployment settings, so they can be tuned for each client.
  • The engine plugs into a socket. A client-specific or hardware-accelerated engine can replace it without touching the router.
  • It runs on the Mac’s own processor and makes no network call.

It is a transparent scoring rule, not a trained neural network. Trained and hardware-accelerated engines are planned for the same socket.

Orchestrator

Big jobs, shared between agents.

There is no separate orchestration server to buy. Orchestration is built into the agent loop and the plugins around it.

Developer preview

  • Parallel tools

    Up to ten independent tool calls run at once in each step. Calls that depend on order run one at a time.

  • Helper agents

    Self-contained tasks go to helpers with a fresh context, working in the background. You can message, interrupt and list them. Up to eight run at once.

  • Coordination scripts

    For a large job, the agent can write a sandboxed script that fans work out to many helpers and returns one combined result.

  • Long goals

    A goal continues round by round, by default for up to 256 rounds. It stops as blocked only when the same blocker persists three rounds in a row.

  • Plan first

    In plan mode, file edits stay locked until you approve a written plan. You can steer a running task without restarting it.

  • Crash-safe

    A checkpoint is written before every model call and every action. An interrupted action is reported as “outcome unknown”, never silently repeated.

Multi-agent work on small local models is still being tested. Agent teams are not offered in this release.

Memory and RAG

Memory you can inspect.
Knowledge that names its source.

Three local stores come built into the default assistant of the Mac app. None of them makes a network call.

Developer preview

  • ISHIZUE Memory

    Facts and preferences you ask it to keep, recalled in later chats.

  • Knowledge Brain

    Project knowledge. Every record names its source: you, or a file in the project.

  • Graph RAG

    Links your team approves between records. A search finds keyword matches, then brings in every record one link away and shows the relation that connected it.

  • Saved only through visible actions, shown as cards in the chat. Ask, and any item is forgotten.
  • Kept as readable files on your Mac, private to your user account.
  • The same records always come back in the same order, with visible scores.

Search works by keywords and approved links today. On-device semantic search is on the roadmap.

Small models

Engineered for the models you can run.

A model on a laptop has a fraction of the memory of one in a data centre. ISHIZUE is built to spend that memory on your task.

  • Tools on demand

    Specialist tools load only when a task needs them. In one measured desktop chat, this started the conversation about 4,000 tokens lighter.

  • Compaction

    Long conversations are summarised automatically before the window fills, keeping the latest part word for word.

  • Big outputs, parked

    A tool result over 4,096 tokens is saved to a file, and the model gets the path instead of the flood.

  • Loop guards

    A model repeating itself is reminded at 3, 5 and 8 identical calls. The tenth is refused.

  • Models sized to your Mac

    A shelf of 12 reviewed open models, each labelled Runs well, Slow or Won’t fit from your Mac’s memory and disk, with the arithmetic shown. Each download is checked and set up with a 32K context for agent work.

Control

You decide what the assistant may touch.

  1. Read only

    The assistant can look, but not change anything.

  2. Workspace write Default

    Where new chats start. Built-in tools keep changes inside the folder you chose and ask before anything wider.

  3. Full access

    No sandbox and no approval prompts. You confirm the risk before it is switched on.

  • Commands the AI runs are confined to the workspace. On macOS they are blocked from connecting directly to the internet while web access is off.
  • Everything the model saw can be rebuilt from the session record, along with each mode, access level and approval.
  • Plugins run inside the app and MCP servers run as their own programs, both outside the sandbox. Approvals do not cover their tools yet. Install and connect only what you trust.

Sandboxing and approvals reduce risk; they are not a guarantee. ISHIZUE has not yet had an independent security audit.

Where it runs

Your Mac, your workstation, your servers.

  1. 01

    This Mac

    Five model apps are detected on the Mac’s own ports, with no setup. ISHIZUE never scans your network.

  2. 02

    Your workstation

    One approved GPU workstation on your private network, over HTTPS. When one is paired, Auto tries it first and falls back to the Mac.

  3. 03

    Your model gateway

    If your company already runs a model server, ISHIZUE can use it through common API formats. Where it runs is your decision.

Tailoring

One core.
An edition for each client.

A client edition is a layer of configuration on the same ISHIZUE everyone runs. It is delivered as settings and plugins, not as a fork.

  • Modes

    Five ship today: Chat, Standard, Code, Minimal and Creator. Your edition adds its own, each with exactly the tools, instructions and skills a role needs.

  • Skills

    Your procedures as skill files, loaded when a task needs them. Edits take effect without reinstalling.

  • Project rules

    Standing instructions in AGENTS.md files, read at the start of work.

  • Persona

    One assistant voice for the whole deployment.

  • Access

    Named access levels and approval rules, set as your defaults.

  • Models

    On the Mac, on your workstation or behind your gateway, with Auto’s weights tuned to your work.

  • Connections

    Your systems through MCP. Mail and calendar under your own registered app are in development.

New capabilities still need plugin engineering, and there is no central admin lock yet: each person can adjust their own settings.

Status

What is ready, and what is not yet.

Developer preview In the developer preview

  • Mac app for Apple Silicon (manual install, early alpha), plus a web interface and command line.
  • Auto routing across models on your Mac and an approved workstation.
  • Helper agents, long goals, plan mode and crash-safe sessions.
  • Memory, Knowledge Brain and Graph RAG, stored locally.
  • Office tools for Word, Excel and PowerPoint files, with PDF export.
  • Optional web search, MCP connections and a Python SDK.

Still in progress

  • Release testing of Auto’s combined ranking of models and thinking modes.
  • Reliable long, multi-step tasks on small local models.
  • A signed, notarised release, and testing on Intel Macs and Windows.
  • On-device semantic search, and memory kept separate for each project.
  • Trained and hardware-accelerated decision engines.
  • KOBO apps such as EMAKI, SOROBAN, FUDE, HANKO and MEKIKI.

Before you decide

  • ISHIZUE is a developer preview, and breaking changes are expected.
  • It has not yet had an independent security audit.
  • Larger models need more memory. Fit labels are arithmetic, not speed tests.
  • Office work and other tool use need a model that is cleared for tools.
