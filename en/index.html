03 · The intelligence inside

Small models, used well.

Models that run on your own hardware are smaller than the giants in the cloud. ISHIZUE is engineered to get more out of them: it reads each task, picks the model that suits it, shares big jobs between agents and keeps memory where you can see it.

  • 01

    Router

    Reads every request before it answers.

    Auto reads each message on the device, in Japanese or English, and sorts it into one of eight kinds of task. A quick reply goes to a small, fast model. Hard work goes to the strongest model you have, with thinking on. A request never goes to a model that can’t hold it.

    How each part works →
  • 02

    Decision engine

    Decides the same way twice.

    One ranked decision weighs every model and thinking mode on five factors, including what you corrected last time. The same inputs give the same answer, and each choice is recorded in the chat with its reasons.

    How each part works →
  • 03

    Orchestrator

    Shares big jobs between agents.

    The main agent runs up to ten independent tool calls at once, hands self-contained tasks to helper agents in the background and pursues long goals round by round, with a checkpoint before every model call and every action.

    How each part works →
  • 04

    Memory and RAG

    Remembers what you ask. Shows where knowledge came from.

    Memories and project knowledge are kept as files on your Mac, and every knowledge record names its source. Graph RAG follows the links your team approves, so related knowledge arrives together.

    How each part works →

04 · Local, precisely

Local by design.
Exact about the exceptions.

Anyone can print “100% local”. We would rather show you what stays on your machines and what can go online, in the Mac app as it is today.

Stays on your machines

  • Every answer from Auto, the local router. It comes from a model on your Mac or on a private server you connect. There is no hosted model and no cloud fallback.
  • Routing decisions. They are made on the device, without calling a model.
  • Memory, project knowledge and knowledge links, kept as files on your Mac. No embedding service, no cloud database.
  • Crash reports and logs. Telemetry is off, we run no collector, and there is no account or analytics.

Can go online

  • Web search, page reading and the AI browser: three separate switches, each off until you turn it on. Search queries then go to a search service.
  • Images in answers. If an answer shows an image from a web address, the chat loads it from there. This is on today.
  • A model server you add yourself in Settings, such as a company gateway. Requests then go to the address you give it.
  • Model downloads, when you press Download, from the model app’s own library.
  • The voice model, downloaded once, the first time you use voice input.

On-premises without us: ISHIZUE needs no Shristyverse cloud service, account or telemetry server. We don’t call it air-gapped, because that has not been tested yet.

05 · Tailored, not generic

Generic AI is built for everyone.
ISHIZUE is configured for you.

Every part of ISHIZUE is a plugin, down to the agent loop. So your edition is a layer of configuration on one maintained core, not a fork that falls behind.

  1. 01

    Only the tools a role needs

    Each mode gives an assistant exactly the tools, instructions and permissions its job requires. Less to misuse, less to audit.

  2. 02

    More room for the work

    Local models have small context windows, and every tool description is sent with every request. Carrying only your tools leaves more of the window for your task.

  3. 03

    Your way of working

    Your procedures become skills that load when a task needs them. Your standing rules live in project files. Your assistant speaks in the voice you choose.

  4. 04

    Kept on the upgrade path

    Your layer sits above the standard ones, so an update replaces ours and leaves yours in place. During the developer preview, each client layer is checked again at every release.

What we configure

  • Modes for each role
  • Skills from your procedures
  • Access levels and approvals
  • Models sized to your hardware
  • Memory and knowledge
  • Japanese and English
  • Your systems, through MCP
